## 术语表

**棋形**（$n=5$ 时）

| 术语 | 含义 | 为什么重要 |
| --- | --- | --- |
| 成五 / five | 5 子连成一线 | 直接获胜 |
| 冲四 / four | 4 子 + 1 个空点可成五 | 对手有冲四，必须占那个点，否则下一手就输 |
| **活四 / open four** | 四子且**两个**不同空点都能成五 | **堵不住**——只能占其中一个。做出活四即锁定胜局 |
| 活三 / open three | 3 子连成一线且两端都空 | 不管它，下一手就变活四 |
| **死线 / dead line** | 该线可用的连续空间已不足 5 格 | 往上加子毫无意义，堵它也毫无意义 |
| 跨度 / span | 一条线上「不含对手子且在盘内」的最长连续段 | 跨度 < 5 即死线，是判定死活的唯一依据 |

**固定测试局面**（`probe.py` / `ablate.py` 里的用例名）

| 用例名 | 局面 | 唯一正解 |
| --- | --- | --- |
| `must_block` | 对手已有冲四 | 占那个成五点 |
| `must_win` | 自己已有冲四 | 占成五点获胜 |
| `make_open_four` | 自己有活三，走一手即成活四 | 占活三的任一端（进攻，等于锁定胜局） |
| `stop_open_four` | **对手**有活三，下一手就变活四 | 占对手活三的任一端（防守） |

**注入档位**（引擎算好的事实，写进请求）

| 位置 | 档位 | 每次注入什么 |
| --- | --- | --- |
| `state`（局面，一整块） | `span` | 每条线的跨度 + 活口数量，不给坐标 |
| | `status` | 再加 `LIVE`/`DEAD` 判定 |
| | `geometry` | 再给活口坐标（防守局面下≈给答案） |
| | `threats` | 再加「对手下一手可在 X/Y 造活四」 |
| `criteria`（每个候选点各一句） | `ways` | 走这里之后对手还剩几条可成五的线 |
| | `windows` | 同上，但句子更复杂（反面对照） |
| | `open_four` | 走这里之后对手能否造活四（**五连层有盲区**） |
| | `threat` | 按优先级报最紧急一层：成五 → 活四 → 都不能 |

**提示词版本**（战术段，`instructions` 字段）

`p0-one-move` 只讲「成五」和「堵下一手的五」·
`p1-threat-ladder` 加入活四/活三定义与六级优先级 ·
`p2-defence-first` 防守优先（仅 jev 用过）·
`p3-open-three-alarm` 把触发条件从推论改成可见形状

**指标**

| 名称 | 含义 |
| --- | --- |
| **正解总概率** | jev 返回的 30 点概率分布里，正确答案那几点的概率之和。比「对错」灵敏得多：0.01 = 完全没进视野，0.35 = 勉强选中，0.97 = 碾压 |
| 排名 | 正解在概率分布里排第几（共 30 个候选） |
| `win_conversion` | 有一步成五机会时抓住的比例 |
| `block_rate` / `of.stop` | 对手冲四时堵住的比例 / 对手能造活四时拦住的比例 |
| `of.make` | 自己能造活四时做出来的比例 |
| `unavoidable_loss` | 对手已有两个成五点，任何一手都救不回 |

## 调查路线（先读这个）

整件事是一条排除链。每一步都是「上一步的结论逼出来的下一个问题」：

```
裸条件下 jev 连输 11 局，格式毫无问题，输的全是棋
   ↓  逐手审计发现：输的那一刻对手已经是活四（堵不住），真正的错误发生在更早（E1–E5）
假设① 它不懂战术 → 把活四/活三的定义和优先级写进提示词，换三个版本
   ↓  完全无效，连一个数字都没动 → 排除（E4, E5）
假设② 它看不见对手的威胁 → 直接问它「这条线还能不能成五」
   ↓  已被堵死的线 0/5 全答「能」，像是真的看不见（E6）
   ↓  但也可能它只是习惯答「能」→ 把这个判断拆成递推链，并用正反两种问法交叉验证
   ↓  读单点、读两端、数连子、算跨度、做 AND/OR —— 全部满分，只有最后的结论错（E7）
假设③ 它不会推理 → 把同一个事实改成纯文字提问，完全不给棋盘
   ↓  10/10 全对，置信度 0.95 → 排除（E8）
定位：会读、会算、会推理，唯独不会「从棋盘自己推导出结论」
   ↓  于是换思路：不再教它推，而是把结论算好喂给它
干预① 把结论写进局面描述（state）→ 固定局面上 0/10 → 10/10（E10）
   ↓  但同一招在实战局面失效：几条线的描述长得一样，事实没有区分度（E11）
干预② 把规则写得更明白、换字段位置 → 0/9，依然无效（E12）
干预③ 把后果写在每个候选点上（criteria）→ 有效，并发现句子结构比内容更关键（E13, E14）
   ↓  实战检验：有效，但我的标注漏了最高的威胁层级，因此仍输一局；修好（E15）
   ↓  再战 48 手，14 次防守任务全部命中，首次不败（E16）
```

读法建议：只想要结论看 [FINDINGS.zh.md](FINDINGS.zh.md)；想知道某个结论是怎么被证明的，
按上面的链条找对应的 E 编号。

## 设置

9×9（部分固定局面 15×15），5 连胜，无禁手。每手给 jev 一个 `choice` 问题，`criteria` 是 30 个
候选点（已有棋子半径 2 内的空点，双方一步杀点强制入选，顺序打乱），返回 choice + 概率分布 +
置信度。jev 每手约 1.7k input / 250 output token / 0.6 秒。

## 实验清单

### E1–E5 摸底：裸条件下的表现（无新发现，高度概括）

五组实验（连通性探针、4 局对战、逐手审计、提示词消融 p0→p1、防守优先版 p2）得到同一个结果：

- **jev 的格式遵循完美**：全程 0 非法落子、0 解析失败、每手一次调用。
- **两个简单层级稳定正确**：`must_block` 5/5、`must_win` 5/5。
- **活四层全错**：`make_open_four` 0/5、`stop_open_four` 0/5，且 5 次重复给出**同一个**错手
  （置信度 0.6–0.85），不存在「多试几次就对」。
- **战术措辞无效**：p0 → p1 → p2 三个版本，上述数字一字未变（10/20 → 10/20）。
- 实战全负。审计显示败因**全部**是 `unavoidable_loss`——输的那一刻对手已是活四，说明真正的
  错误发生在更早，而当时的指标（只覆盖成五层）看不到。

E3 暴露的指标盲区后来补上了活四层（`of.make` / `of.stop`），E5 唯一可见的变化是 p2 让它从
「往自己死线上加子」变成「贴着对手的线走」——但堵在平行位而不是活口，属于换个方式输。

### E6 它到底看见了什么：第一次直接问

**为什么做这个** 前面五组已经排除了「不懂战术」。剩下的嫌疑是它根本没看见对手的威胁。但对局
记录只能告诉我们「它走了哪一步」，看不到「它眼里的棋盘是什么样」。

**怎么问** jev 的 API 允许**一次请求里问多个问题**（官方叫 fan-out）。于是在问「你走哪一步」的
同时，夹进一批**引擎已经知道正确答案**的是非题。这样同一个局面、同一次请求，既拿到它的选择，
也拿到它的「认知」，两者可以直接对照。

**关键那一问：死线**

一条线如果两端都被对手的子堵住，剩下的空间就凑不满 5 个格，永远不可能成五——这叫**死线**。
往死线上加子、或者花一手去堵对手的死线，都是纯浪费。所以「这条线还能不能成五」是最能区分
「看见了」和「没看见」的问题。

同时必须问一条**活线**（两端还空着、确实能成五的线）作为对照。否则如果它对所有这类问题一律
回答「能」，我们无法区分「它看不出死线」和「它只是习惯答能」。

**结果**（6 个局面合计，括号内是正确答案）

| 问的是什么 | 正确率 |
| --- | --- |
| 这条**活线**还能成五吗（应答「能」） | **8/8** ✓ |
| 这条**死线**还能成五吗（应答「不能」） | **0/5** ✗ |
| 我这一手能不能直接成五 | 5/6 |
| 对手是不是已经四连了（我必须堵） | 5/6 |
| 我 / 对手能不能走一手就造出活四 | 3/5 · 2/5 |
| 它实际落子是否等于客观最佳解 | 2/6 |

**怎么读这个结果**

前两行是同一个问题、相反的正确答案，而它两次都答「能」——**活线全对、死线全错**。更关键的是
概率：死线那 5 次给的是 0.63–0.85，活线那 8 次给的是 0.61–0.91，**两个区间完全重叠**。也就是说
它的回答里没有任何能用来区分死活的信号。

倒数第二行（造活四 3/5、2/5）呼应了 E1–E5 的老问题：活四这一层它本来就不稳。最后一行说明
落子质量确实很差：6 个有唯一正解的局面只走对 2 个。

**留下的歧义** 这批死线问题的正确答案**全是**「不能」，活线问题**全是**「能」，而它一律答「能」。
所以「它看不出死线」和「它对这种句式一律答能」两种解释都成立，无法区分 → 这直接催生了 E7。

### E7 递推链拆解：能读、能数、能组合，就是推不出结论

**为什么做这个** E6 留下的歧义必须先排除：它是真的看不出死线，还是只对这种句式一律答「能」？

**怎么做** 把「这条线还能不能成五」这**一个**判断，拆成人做这道题时会经过的每一小步，对**同一
条线**在一次请求里全部问一遍。这样如果它在某一步之前都对、之后才错，断点就精确到了那一步。

同时把最终结论用**正反两种问法**各问一次（「还能成五吗」和「是否已不可能成五」）。如果两个都
答「是」，那就是纯附和，跟理解无关——这是针对 E6 那个歧义设计的对照。

5 个局面（两端被堵 / 只堵一端 / 两端全空 / 两子的死线 / 靠边线的死线）× 2 次重复：

| 类别 | 问题 | 结果 | 概率 |
| --- | --- | --- | --- |
| 原子 | `D5` 是白子吗 | 10/10 | 0.99 |
| 原子 | **左端**是否被堵 | **10/10** | 0.99 |
| 原子 | **右端**是否被堵 | **10/10** | 0.99 |
| 原子 | 可用跨度多长（≤2/3/4/≥5） | **10/10** | — |
| 原子 | 有没有 4 子连线 | 10/10 | 0.99 |
| 组合 | 两端是否都是白子（**AND**） | **10/10** | — |
| 组合 | 至少一端是白子（**OR**） | **10/10** | — |
| 组合 | 两端是否都**空**（AND + 极性反转） | 7/10 | 0.38–0.56 |
| **结论** | 还能成五吗 | **4/10** | 0.50–0.79 |
| **结论** | 是否已不可能成五 | 7/10 | 0.12–0.48 |

AND / OR 都满分，**合取不是问题**。最刺眼的是它算对了跨度（含靠边线那个答 4、两子那个答「≤2」），
却在「4 < 5 ⇒ 成不了五」这一步翻车。正反矛盾仅 2/10，所以不是附和。

第一版只问了「某一端是不是白子」和「两端是否都空」，后者 8/10 让人误以为「大致能看两端」；
**把单端拆开问之后才发现单端是 10/10，问题在别处**。

### E8 断点隔离：事实 vs 反事实

**为什么做这个** E7 把断点定位到了「有了全部事实、却推不出结论」这一步。那么问题出在**推理
本身**，还是出在**从棋盘取事实**？三组问题分别掐住一种可能：

① **纯规则算术**：完全不给棋盘，把局面用一句话描述（「某方有 4 连、两端被对手占」），问同一个
问题。如果这里也错，说明推理本身不行。
② **三色辨别**：同一个点分别问「是白子吗 / 是空的吗 / 是黑子吗」。用来检验一个具体猜想——
它会不会分不清「空」和「有子」。
③ **结论换成计数形式**：不问「还能不能成五」（是非题），改问「还能再加几个子」（数量题），
看是不是问法导致的。

| 组 | 结果 | 概率 |
| --- | --- | --- |
| 抽象规则（不看棋盘，5 问） | **10/10** | 0.95–0.97 / 0.07–0.14 |
| 三色辨别（54 问） | **54/54** | 0.98–1.00 / 0.01 |
| 「还能再加几个子」 | **1/10** | 0.24–0.66 |

决定性的一组对照，同一事实两种呈现，答案相反：

| 呈现 | 问题 | 回答 |
| --- | --- | --- |
| **文字** | 某方有 4 连、两端被对手占，还可能成五吗 | **否，p=0.13** ✓ |
| **棋盘** | 同一局面，黑 E5 F5 G5 H5 还能成五吗 | **能，p=0.61** ✗ |

而且会自相矛盾：同一条线「含自身的跨度」答「≤2」（对），「还能再加几个」答「3 个以上」（错）。

**由此排除的假设**（都是实验证否，不是推测）：看不见棋盘 ✗（读点 0.99）· 分不清空与白 ✗（54/54）·
不会合取 ✗（AND/OR 各 10/10）· 不懂规则 ✗（抽象 10/10）· 只会附和 ✗（矛盾仅 2/10）·
战术措辞不到位 ✗（三个版本无变化）。

### E9 差异是否 jev 特有（一句话）

**为什么做这个** 上面这些问题会不会本身就很难、任何模型都答不好？把同一套题翻译给另一个后端
问一遍就能知道。

同一套问题、同一局面翻译给对照后端各问一次：**事实类 124/124 双方相同、纯文字规则推理 10/10
双方相同、从棋盘推反事实 jev 19/40 而对照 40/40**。即差异不是「这些问题本身难」，而是集中在
jev 的这一项能力上。

### E10 事实注入（固定局面）

**为什么做这个** E8 证明它能用**文字给出的前提**正确推理，只是不会自己从棋盘里把前提提炼出来。
那就别再教它推——直接把引擎算好的结论写成文字喂进去。

**四档递进**是为了知道「到底哪一层信息是必需的」：只给数字 → 加上死活判定 → 再给坐标。
分档还有一个作用：如果只给数字就够了，说明它缺的确实只是「把数字变成结论」这一步。

每格 5 次重复：

| 局面 | `none` | `span` | `status` | `geometry` |
| --- | --- | --- | --- | --- |
| `make_open_four`（进攻） | 0/5 | 0/5 | **5/5** | 5/5 |
| `stop_open_four`（防守） | 0/5 | **5/5** | 5/5 | 5/5 |

**注入有效，且不是抄答案**：`status` 档达到 10/10，而该档文本**不含任何坐标**。

**我事前登记的预测错了**：我预测几何事实无效（理由是 E7 显示它自己就能算对跨度），实际 `span`
档已把防守题从 0/5 拉到 5/5。这说明它**能**算跨度，但选点时**不会去算**——没写在文本里的东西
不进入决策。

过程中修掉两个自制漏洞（都是先发现再修、修完重跑）：`geometry` 档把活口坐标写进文本，而防守题
的正解就是那两个坐标；`status` 档的理由行原本也带坐标。为此新增只给数量不给坐标的 `span` 档。

### E11 定点复盘：那一手为什么不堵

**为什么做这个** E10 在人造的固定局面上成功了。但固定局面是我挑的，可能天然比实战简单。所以要
拿**实战里真实输棋的那一手**重做一遍，看结论还成立吗。

**怎么做** `postmortem.py` 从任一对局记录里取出某一手之前的局面，用**该手当时收到的同一份候选
菜单**（这点很重要，否则换了菜单就不是同一道题），问三类问题：它看见了什么、能不能指出该走
哪里、以及在各个注入档位下会怎么选。

样本：实战第 6 手。对手已摆出斜线活三（两端全空），jev 走了个无关点，两手后输棋。

| 问题 | 真值 | jev | 概率 |
| --- | --- | --- | --- |
| 对手有 3 连吗 | 是 | 是 ✓✓ | 0.60 / 0.63 |
| 那条线还能成五吗 | 是 | 是 ✓✓ | 0.66 / 0.64 |
| 两端都是空点吗 | 是 | 是 ✓✓ | 0.65 / 0.63 |
| 哪个点在那条线端点上 | C7/G3 | **G3** ✓✓ | 0.42 / 0.38 |
| **对手下一手能造双成五点吗** | 是 | **否** ✗✗ | **0.36 / 0.38** |
| **活四能被堵住吗（纯规则）** | 否 | 是/否 ✗✓ | **0.51 / 0.48** |
| **哪个点能阻止对手** | C7/G3 | **它自己那手** ✗✗ | 0.35 |

三连、活线、两端空、端点定位全对。断在「三连两头空 ⇒ 对手下一手就不可阻挡」这一步，以及
「活四堵不住」这条规则本身（等于抛硬币）。直接问「哪个点能阻止」时，它答自己想走的那手。

同一手的注入 A/B：`none` 0.01 → `span` 0.15 → `status` 0.09 → **`threats` 0.97**（落子改对）。

**这修正了 E10**：E10 里 `span` 就够，这里 `span`/`status` 都失效。因为本局面两条线的事实描述几乎
一样（都 LIVE、都 2 活口、跨度 8 对 9），**事实块没有提供区分度**。E10 的局面只有一条活线，数字
一摆就无歧义。

它的打分同时跟着「离自己的子多近」走：概率 ≥0.13 的 3 个点平均距自己的子 1.00，概率 <0.02 的
18 个点平均 2.17，两个正解点距自己的子 2–3 格、拿 0.00 和 0.01。

### E12 把「活三必死」写进战术，以及换字段

**为什么做这个** E11 让我重读了提示词，发现 p1 里那条防守规则的**触发条件写错了对象**：原文是
「如果对手下一手能造出活四，就去破坏那条线」——而「对手下一手能不能造活四」恰恰是它答 0.36 的
那个推论。动作部分写得没问题，但条件永远触发不了。

于是把触发条件换成它**看得见**的东西（三连 + 两端空，这个它答 0.60–0.66 全对）。新建 `p3-open-three-alarm`：触发条件改成
它**看得见**的形状（"the moment the opponent has 3 stones in an unbroken line with an empty point
at BOTH of its ends, you have one turn left to act"），并写明回应方式。再加一臂：同样文字从
`instructions` 搬到 `state`。

| 条件 | 选对 | 正解概率 |
| --- | --- | --- |
| p1，战术在 instructions | 0/5 | 0.01 |
| **p3，战术在 instructions** | **0/6** | 0.02 |
| **p3，战术在 state** | **0/3** | 0.02 |
| p1 + `state` 注入 `threats` | 2/2 | **0.96** |

**结论** 把「活三必死」写进战术**不管用**（两个字段合计 0/9），**也不是字段位置的问题**——同一段
文字放 `instructions`（0.02）和放 `state`（0.02）表现一样。而同一批请求里它仍然答对「有三连」
「两端都空」「哪个是端点」：**看得见形状、被告知形状致命、被告知该走哪种点，依然不改。**

对照最后一行可以看出唯一起作用的东西：一句关于**这个局面**的具体陈述（「对手可在 C7 或 G3 造
活四」），把正解概率从 0.01 推到 0.96。规则不行，事实才行。

### E13 把后果标在每个候选点上

**为什么做这个** E12 证明规则文字无效、只有关于当前局面的具体陈述有效。那就换个落点：不描述
棋盘上的线，而是**逐个候选点**说明「走这里会怎样」。

顺带回答一个一直没测的问题——jev 到底读不读 `criteria` 字段里的文字。那一栏是每个候选点的说明
文字，此前一直是句废话（`Play at column D, row 7.`，只是把坐标复述一遍），而所有注入都放在
`state` 里。

| 条件 | 落子 | 正解概率 | 排名 |
| --- | --- | --- | --- |
| `criteria` 无标注 | ✗ ×3 | 0.00–0.01 | 14–30 |
| **`criteria` 标注后果** | **✓ ×3** | **0.69–0.71** | **1 / 2** |

**`criteria` 的文字会被读取且有效**——这一栏此前一直浪费着。三个通道的影响力由此排定：
`instructions`（规则）≈ 无效 < `criteria`（逐选项事实）< `state`（局面事实）。

取舍：本局面 30 个候选里只有 2 个被标为安全，等于把答案标出来。所以这条只能读成「`criteria`
会被读取」，不能读成「jev 学会防守了」。

### E14 收紧成「不等于答案」的连续量，以及措辞的威力

**为什么做这个** E13 的标注在防守局面里只把 2 个点标成「安全」，等于把答案圈出来了。要检验它是
**真的在用这条信息**，标注就不能等于答案——得换成一个连续的量，让它必须**比较数字**而不是读一个
判决词。

改用「此手之后对手还剩几条可能成五的线」。本局面的梯度是真实三级：堵端点剩 1 条、堵在窗口内部
剩 2 条、其余 27 个点剩 3 条。

| 标注 | 文案形式 | 落子 | 正解概率 |
| --- | --- | --- | --- |
| `none` | — | ✗ ×3 | 0.01 |
| `windows` | 两个从句、两个数字 | **✗ ×3** | **0.02** |
| **`ways`** | **一句话、一个数字** | **✓ ×3** | **0.33–0.38** |
| `open_four` | 判决式 | ✓ ×3 | 0.68–0.70 |

同一个数字，两种写法：

```
windows: "the opponent's best still-winnable line holds 3 of the 5 points it needs,
          and 1 line(s) on the board are that far along."      → 0.02（等于没标）
ways:    "the opponent has 1 different ways left to reach 5 in a row."
                                                               → 0.35（生效）
```

**连续量可用**（我在 E12/E13 写的「只有判决式有效」过强，已更正）；**句子结构能盖过内容**，
逐选项标注必须一句话一个数字；**判决式仍最强**（0.70 vs 0.35）。

如果在 `windows` 那一臂收手，就会得出「它不会比较数字」这个错误结论——靠追加一个**只改措辞**的
对照臂才排除。

### E15 实战暴露的注入盲区，以及修复

**为什么做这个** 前面都是单个局面的测试。要知道这套注入在**整局**里管不管用，只能实战。

用 E13 的 `open_four` 标注打一局。**在它覆盖的层级上有效**：撑到 16 手（此前 9–12 手），
并**首次**拦住活四（2/2）。**但输在覆盖不到的那一层**：第 15 手对手已斜线四连、唯一成五点 B3，
当时发出的 `criteria` 是——

```
30 项，30 句一模一样：
"... After this move the opponent cannot create an unstoppable open four on their next turn."
```

去重后只剩 1 种句式 → 这一手等于没注入。根因在 `analysis.open_four_moves()` 第一行
`if winning_moves(...): return []`（注释写的是「已经能赢，下一层级已无意义」）。这对**判分**
正确，拿去**做提示**则整层失声：每个选项都说「对手造不出活四」，字面为真、毫无信息，而其中 29
个点走完对手下一手就成五。

| 标注 | 落子 | B3 概率 | 排名 | confidence |
| --- | --- | --- | --- | --- |
| `none` | ✗ ×3 | 0.00 | 23–30 | 0.29–0.32 |
| `open_four`（盲区版） | ✗ ×3 | 0.00–0.01 | 22–30 | 0.23–0.26 |
| **`threat`（修复版）** | **✓ ×3** | **0.79–0.81** | **1** | **0.78–0.82** |

有／无标注下 B3 都是 0.00，所以旧标注没有「害」它；但修好之后同一手立刻堵对。**结论：jev 漏这
个斜线四连是因为没人告诉它，不是因为告诉了也不理。**

修复：新增 `--option-facts threat`，按优先级报最紧急一层（成五 → 活四 → 两回合内无法取胜）。
保留 `open_four` 不动以维持 E13/E14 数据可比，并加回归测试钉住盲区。

顺带修掉 `postmortem.py` 两个 bug：算端点时把「为显示而按列重排的坐标」与「连段原方向」混用，
反斜线局面会算到连段内部（导致 jev 答对却被标成 ✗）；判分目标硬编码成活四点，五连局面下为空。

### E16 修复后的实战：首次不败

**为什么做这个** E15 修掉了标注的覆盖盲区，需要一局实战确认「两层都覆盖之后还会不会有第三类
失分方式」。

`--option-facts threat`（仅 jev），9×9，48 手。

| | 裸条件（3 局） | `open_four`（E15） | **`threat`（本局）** |
| --- | --- | --- | --- |
| 手数 | 9 / 12 / 12 | 16 | **48** |
| 防守机会 → 成功 | 0/1, 0/1, 0/1 | 2/2 活四层，0/1 成五层 | **14/14** |
| 堵成五 | — | 0/1 | **6/6**，最高 conf 0.95 |
| 拦活四 | 0% | 100% | **8/8** |
| 结果 | 全负 | 负 | **胜（对手弃权）** |

**结论** **14 次防守任务全部命中、零失误**，注入的有效性在 48 手长局里得到确认；对比裸条件下
0/3，这是这一系列干预最直接的成果。

**两条必须写明的保留**：**jev 全程没有一次进攻机会**（`win_conversion` 为空，从未形成一步杀），
它做的唯一一件事是不输，而「不输」由调用方的引擎逐点算出威胁换来——**这是分工胜利，不是棋力
胜利**。对手的弃权原因是它自己的输出预算耗尽（连续三次返回空内容），而那个上限是我设的，
因此本局**不能**当作棋力对比的证据。

## 方法论教训

1. **截断会伪装成解析失败**：要看 `finish_reason`，不能只看解析结果。
2. **单次采样不可信**：所有结论都要重复采样。
3. **复合问句制造假信号**：「两端是否都空」8/10 让我误以为「大致能看两端」，拆成单端后才发现
   单端是 10/10。诊断题要拆到原子。
4. **指标有盲区**：只测成五层时，真实败因（放任活三变活四）完全不可见。
5. **正反问法**是排除附和的廉价手段。
6. **对照组要留在代码里**：`p0-one-move` 作为对照版本保留，随时能重跑。
7. **不同提示词/注入档的数据不能混**：每条记录都带 `prompt_version` / `facts` / `option_facts`。
8. **固定局面上有效的干预，未必在实战局面上有效**（E10 vs E11）。固定局面往往只有一条活线，
   信息天然有区分度；真实局面里多条线长得一样，同一段事实就失效。干预必须在实战抽取的局面上复验。
9. **带后果的问题会被模型偏好污染**：同一请求里「哪个点在端点上」答对、「哪个点能阻止对手」
   就退回它自己想走的那手。几何问题和后果问题要分开问。
10. **规则 ≠ 事实**：写进提示词的规则（无论措辞、无论字段）几乎不影响选择；只有关于当前局面／
    当前选项的具体陈述才有效。
11. **句子结构能盖过内容**：同一个数字，两从句被完全忽略（0.02），单句就生效（0.35）。
12. **负面结果先排除表述问题**：任何「模型做不到 X」的结论，都要先换一种说法重试。
13. **注入必须覆盖所有威胁层级**：只覆盖一层的标注，威胁升级时会退化成「每个选项同一句话」。
    自检办法：统计标注文本的去重数量，若为 1 则这一手等于没注入。
14. **给判分用的函数不能直接拿去做提示**：`open_four_moves` 在「已能取胜」时返回空集对指标正确，
    对标注致命。
